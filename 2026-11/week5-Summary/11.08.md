# 11-09 

## 今天学了/做了什么

-了解了事务：事务是一组操作的1集合，这组操作，要么全部执行成功，要么全部执行失败。
事务的操作：start transaction(开启事务) commit/rollback(提交/回滚)
事务的四大特性：(ACID)原子性，一致性，隔离性，持久性。
并发事务问题：脏读，不可重复读，幻读。感觉这些问题可能会出现在实际开发过程，脏读就是在两个命令行窗口中，一个事务读到了另一个事务没有提交的数据，如果那个事务回滚（rollback）了，那读到的数据就是无效数据；不可重复读:一个事务内，多次读取同一行数据，但由于另一个事务在此期间修改（Update/Delete）并提交了该数据，导致前后读取的结果不一致。幻读：一个事务内，多次执行同一个查询，由于另一个事务在此期间插入（Insert）或删除（Delete）并提交了数据，导致第二次查询返回的行数变多了或变少了。
有四种隔离级别：Read Uncommitted：什么都不管，最低级。（啥问题都防不住）
Read Committed：只能读到别人已经提交的数据。（能防脏读）<这是 Oracle、SQL Server 等数据库的默认级别>
Repeatable Read：保证在同一个事务里，你刚开始读到的数据是什么，后面就一直是什么（即使别人修改并提交了）。（能防脏读、不可重复读）
<这是 MySQL InnoDB 引擎的默认级别。>
Serializable：最高级，完全串行执行，排队来，一个接一个。（能防脏读、不可重复读、幻读）,但性能最低

create table account(
                        id int auto_increment primary key comment '主键ID',
                        name varchar(10) comment '姓名',
                        money int comment '余额'
) comment '账户表';
insert into account(id, name, money) VALUES (null,'张三',2000),(null,'李四',2000);


-- 恢复数据
update account set money = 2000 where name = '张三' or name = '李四';

-- 方式1
select @@autocommit;
set @@autocommit=0;-- 设置为手动提交

-- 转账操作
select * from account where name='张三';

update account set money=money-1000 where name='张三';
程序运行报错...
update account set money=money+1000 where name='李四';

commit;

rollback;
